# Product

## Register

product

## Users

Business users describe software and operating needs in their own language while an agent turns
the conversation into working software. They need to understand progress without knowing how the
worker, provider, or development environment operates.

## Product Purpose

Make software creation approachable to people who do not write code. The interface succeeds when
someone can state a need, refine it with the agent, and always understand whether their input was
saved, what is happening now, and whether they need to act.

## Brand Personality

Restrained, capable, and direct. The product should feel calm during long-running work and precise
when something is unavailable or fails.

## Anti-references

- Consumer messaging interfaces that frame the user and agent as two peers trading chat bubbles.
- Generic admin templates whose decoration competes with the task.
- AI SaaS styling built from gradients, glass effects, oversized radii, or ornamental motion.

## Design Principles

- Tell the truth about system state and the next action, especially while work is queued or running.
- Keep the requirement and the agent's answer primary; fold implementation activity without hiding failure.
- Preserve user input across recoverable errors and avoid asking people to repeat work.
- Use familiar product controls and reserve emphasis for active selection, progress, warning, and failure.

## Accessibility & Inclusion

Meet WCAG AA contrast and interaction requirements. All controls must work from the keyboard,
dynamic status changes must be announced without reading every streamed token, and motion must
respect `prefers-reduced-motion`. Chinese and English are first-class interface languages.
